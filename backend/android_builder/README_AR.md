# خدمة بناء APK المعزولة

هذه خدمة مستقلة عن API الرئيسي. لا تمنحها Docker socket ولا مجلدات المشروع أو أسرار المستخدم. شغّلها في حاوية منفصلة، بمستخدم غير root، وذاكرة/CPU محدودة، وقرص مؤقت، وشبكة خروج مقيدة إلى مستودعات Android/Gradle المطلوبة فقط.

متغير `ANDROID_BUILDER_TOKEN` يجب أن يكون سراً قوياً مشتركاً مع API باسم المتغير نفسه. اضبط `ANDROID_BUILDER_URL` في API على عنوان HTTPS، أو عنوان HTTP داخلياً موثوقاً مثل نطاق `.railway.internal`. يرفض API عناوين HTTP العامة وروابط بيانات الاعتماد والمسارات غير المتوقعة. لا تعرض المنفذ للعامة؛ استخدم شبكة الخدمات الخاصة.

البناء يستخدم Gradle 8.7 وJDK 17 وAndroid SDK 35. يقبل العامل ملفات قالب NatqAI المعروفة فقط، ويتحقق من تطابق ملفات Gradle وManifest وMainActivity بايتاً ببايت مع القالب الموثوق قبل البناء؛ أي تعديل أو ملف مصدر إضافي خارج `assets/www` يُرفض. لذلك لا ينفّذ العامل Gradle scripts أو Java/Manifest يرفعها المستخدم. ملفات التطبيق داخل `assets/www` فقط هي التي تُضمّن كما هي. المهلة 10 دقائق، والحدود 25 MiB للمصدر و550 ملفاً و100 MiB للـ APK. كما يرفض العامل طلب HTTP الكامل الذي يتجاوز 26 MiB قبل أن يبدأ محلل multipart بتخزين الملف المؤقت؛ ويطبق الحد أيضاً على الطلبات التي لا ترسل Content-Length.

مثال تشغيل محلي بعد بناء الصورة:

```sh
docker build -f backend/android_builder/Dockerfile -t natqai-android-builder backend
docker run --rm --read-only --tmpfs /tmp:rw,nosuid,size=2g --memory=3g --cpus=2 --pids-limit=128 \
  --cap-drop=ALL --security-opt=no-new-privileges \
  -e ANDROID_BUILDER_TOKEN='ضع-سراً-قوياً-هنا' -p 127.0.0.1:8088:8080 natqai-android-builder
```

لا تضع السر في Git أو ملفات ZIP. يجب توفير مساحة مؤقتة كافية لبناء Gradle. لا تعتبر الخدمة جاهزة للإنتاج قبل تقييد الشبكة، ومراقبة الموارد، وضبط TLS وتدوير السر.

## فحص الجاهزية والتحقق من APK

- `GET /health` يفحص أن خدمة HTTP تعمل فقط.
- إعداد Railway يجب أن يستخدم `/health` لفحص الخدمة؛ لا تستخدم `/ready` في فحص Railway لأنه يتطلب رمزاً سرياً. NatqAI API وحده يستدعي `/ready` مع Bearer token للتحقق من أدوات البناء.
- `GET /ready` يتطلب ترويسة `Authorization: Bearer <ANDROID_BUILDER_TOKEN>`، ثم يفحص وجود Gradle وJDK وAndroid SDK قبل قبول التشغيل. لا يكشف تفاصيل الجاهزية إلا لحامل الرمز الصحيح.
- قبل البناء يقارن العامل ملفات `settings.gradle` و`build.gradle` و`gradle.properties` و`app/build.gradle` وManifest وMainActivity بالقالب الموثوق حرفياً، ويرفض أي تغيير فيها أو أي ملف مصدر إضافي خارج `assets/www`.
- بعد البناء يتحقق العامل من سلامة ZIP ووجود `AndroidManifest.xml` و`classes.dex`، ولا يكتفي بتوقيع الملف.
- يتم حفظ سجل Gradle في مجلد مؤقت محدود الحجم ثم حذفه؛ لا يُرسل السجل الخام للمستخدم.
- توجد طبقة ASGI تحد حجم جسم طلب `/build` إلى 26 MiB تقريباً قبل تحليل multipart، بما يشمل الطلبات المتدفقة التي لا ترسل `Content-Length`.
- يجب أن يكون اتصال الشبكة الخارجة محدوداً بمستودعات Gradle وAndroid اللازمة، مع عدم كشف الخدمة للعامة.

## التحقق من توقيع APK

بعد نجاح Gradle وفحص بنية APK، يشغّل العامل أداة `apksigner verify --verbose --print-certs` من Android SDK Build Tools 35 للتحقق من وجود توقيع Android صالح. إذا كانت الأداة غير موجودة أو فشل التحقق، لا يُسلّم APK إلى المستخدم. لذلك أصبحت `apksigner` جزءاً إلزامياً من فحص جاهزية العامل `/ready`.

هذا التحقق يثبت صحة توقيع APK الناتج، لكنه لا يحوّل نسخة Debug إلى إصدار إنتاج. نشر تطبيق على Google Play يتطلب إعداد مفتاح توقيع إنتاجي وإدارة أسراره خارج ملفات المشروع، ثم بناء إصدار Release وتوقيعه وفق سياسة الإصدار.

## إيقاف البناء والتنظيف عند انقطاع الاتصال (v35)

- تشغيل Gradle أصبح غير حاجب لحلقة أحداث خدمة FastAPI، حتى تستطيع الخدمة اكتشاف انقطاع العميل أثناء البناء.
- عند انقطاع العميل أو انتهاء مهلة البناء، يرسل العامل `SIGTERM` إلى مجموعة عمليات Gradle كاملة، ثم `SIGKILL` بعد مهلة سماح قصيرة إذا بقيت عمليات معلّقة.
- يستخدم البناء جلسة/مجموعة عمليات مستقلة حتى لا تبقى عمليات Gradle الفرعية بعد إلغاء الطلب.
- يحذف مجلد العمل المؤقت في جميع مسارات الفشل والإلغاء. وعند نجاح البناء، يبقى المجلد حتى انتهاء إرسال APK ثم يحذف في كتلة `finally` حتى إذا انقطع اتصال التنزيل.
- لا تزال سجلات Gradle محلية داخل المجلد المؤقت ولا تُعاد للعميل.
